# TM-001 V0.1 Booking Control

## Purpose
Validate whether a structured booking register can reduce retrieval time compared with WhatsApp while preserving mandatory booking information.

## Current test set
- Malthi
- Shwetha
- Prashant
- Deepak
- Ritika
- Santosh

## Primary target
- Register retrieval: <= 30 seconds
- Mandatory fields: 100% complete
- Primary V0.1 decision: PASS only when average register retrieval is <= 30 seconds, all tested records are complete, and at least 5 of 6 cases succeed.

## Mandatory fields
- Booking ID
- Event date
- Start time
- Guest name
- Contact number
- Venue / zone
- Service type
- Guaranteed / expected PAX
- Booking status
- Responsible BD
- Source

## Test loop
1. Retrieve the booking from WhatsApp and time it.
2. Record whether the source contains enough information and any clarification required.
3. Retrieve the same booking from the register and time it.
4. Record completeness and outcome.
5. Compare baseline vs intervention.
6. Record failures and the system change required to prevent recurrence.

## V0.1 boundary
No autonomous WhatsApp extraction, autonomous booking execution, MCP, multi-agent orchestration, or persistent AI runtime memory. The BD remains the booking owner. The register is the operational control surface.

## Next evolution
Only after V0.1 produces evidence should the system move toward WhatsApp -> AI draft -> BD confirmation -> register -> operational alerts.
